## The rules, and why they exist

The first attempt to package this work was thrown out because the agent doing it, under an explicit instruction not to fabricate, filled an empty results table with a relabeled chat response and reported judge agreement from a model scoring itself. The harness now refuses those moves in code. You will still be tempted to work around the refusals when something fails. Don't.

1. **Never fabricate, estimate, or relabel a result.** A missing key is `ENV_MISSING_API_KEY`. An API failure is `API_ERROR`. An empty table stays empty and says why. If you cannot run something, the deliverable is the honest empty state plus one sentence explaining what blocked you.
2. **Never edit `results/raw/*.json` or `results/scores/*.json` by hand.** Provenance is set by the code. Judge records are re-validated on every read, including recomputing their means from the cell-level output; a hand edit raises an integrity error at the next aggregation.
3. **Phase 2 takes `api_run` rows only.** The human transcript is a baseline exhibit. The validator refuses it in Phase 2. Do not "fix" the validator.
4. **Judges are cross-family, enforced by exception.** Do not reorder `judge_order` in `models.json` to make a same-family pairing pass, do not use `--force` to overwrite a `COMPLETED` judge record without a reason logged in `DECISIONS.md`, and do not score mock transcripts with real judges or real transcripts with the mock judge (the code refuses both).
5. **Do not change the article's substance, the scenario user turns, or the rubric semantics** without a `DECISIONS.md` entry and a version bump on the file you changed. Fixing a typo is fine. Softening a scenario because a model did badly on it is not.
6. **Do not write numbers into README prose.** `README.md` is generated by `build_readme.py` from `README.template.md`. Edit the template. The tables come from `results/`. If you want to add a findings paragraph after results exist, write it in the template, take every number from the generated tables, and state `n`.
7. **Log every judgment call** in `DECISIONS.md` as a numbered item with one line of reasoning. Newest at the bottom. The audit round is 27–36; continue from 40.
8. **Commit in logical units, authored as Dino Silvestri.** Do not squash the history.

### Step 5: read the results before writing about them

Before adding a findings paragraph to the template, check these, in order, because each one can make a result look like something it is not:

- **Judge agreement.** If pooled κ on binary cells is below about 0.6 or MAD on 0–2 cells is above about 0.4, the judge is noisy enough that model-to-model differences inside that band are not findings. Say so. Consider `python judge.py --audit-fraction 1.0 --force` on the scenario in question to get full dual coverage.
- **The fixed-script artifact.** In `s1_pizza`, a model that states the cost in turn 1 will look worse on turns 4–11 because the script yells at it anyway. Report `T1_UNPROMPTED_COST` and `FIRST_SUBSTANTIVE_TURN` as the headline for that scenario, not the later-turn means. `methodology.md` explains this.
- **The control.** If a model scores well on `s4_cigarettes` and badly on `s0_control_gym` (high F7, `L1_UNWARRANTED_HEDGE` true), it is a scold, not a success. The point of the pair is that both must be right.
- **Phase 2 circularity.** The directive is the rubric restated as imperatives. A Phase 2 improvement shows the behavior is reachable when asked for in the rubric's vocabulary. It does not show generalization. Write it that way.
- **n.** Three runs plus one at temperature 0 per cell. Enough for large gaps between models or phases. Not enough for close calls. Say which kind each claim is.

Then write the findings paragraph in `README.template.md`, every number traceable to a table, and regenerate.

### Step 6: what would make it stronger (optional, propose before building)

Each of these needs a `DECISIONS.md` entry proposing the design before any code changes, because each touches the integrity rules.

- **Hand-scored sample.** Ten transcripts scored by a person against the same rubric, to validate the LLM judge. This needs a new judge family value (something like `human`) in `she/common.py`, with the cross-family rule treating it as always valid. Propose the schema first.
- **Held-out directive rephrasing.** A second system prompt that states the EHD's rules in different words, to test whether Phase 2 gains survive a vocabulary change. Add it as `prompts/ehd_system_prompt_rephrased.md` and a third phase; the phase list is in `she/common.py`.
- **A second author's scenarios.** The five scenarios were written by the person who observed the failure. Scenarios from someone else, run through the same rubric, address the leading-the-witness limitation.
- **Clinician review.** The physiology in each scenario's `judge_guidance` is mainstream but unreviewed. A clinician's sign-off, or corrections, logged with their name if they consent.
- **App-side transcript export.** If the original Gemini session can be exported from the Gemini app, it replaces `docs/transcript_original.md` and the raw exhibit. Diff it against the current file and record any differences.

## Context the files don't carry

- The author frames this as blue-team work: document the break so the fix is specific; the fix is the deliverable. He is not interested in "look how broken the model is" content, and the README should never read that way.
- The rule under everything: the standard of care is set by the person's body and situation, never by the user's tone, guilt, or framing. It cuts both ways. A model that learns only to state costs becomes a scold; that is why `s0` exists and why F7 mirrors F1.
- "Argon" in the author's notes means Gemini (`gemini-4-argon`). The original subject was Gemini Flash/Live in voice mode. The first packaging attempt was also a Gemini session. None of that is a verdict on Gemini; the whole point of the harness is to run every lab's models through the same scripts.
- The prompt that produced the rejected first attempt had a gap: it never said what to do when zero API runs exist. The agent filled the gap with a fabrication. This handoff closes that gap explicitly: an empty table, labeled, is a valid and expected deliverable.
- The author expects pushback when he is wrong and does not want validation. If a result contradicts the article's thesis, report it plainly. That outcome would be more valuable than a confirming one, and he knows it.
